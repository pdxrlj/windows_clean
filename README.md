# CleanSweep

**Windows 上更彻底的软件卸载工具——卸载完接着清残留。AI 只给建议，删什么你说了算。**

Windows 10 1809+ / 11（x64）· 需要管理员权限 · 无需注册 · 无遥测

![软件列表](docs/screenshots/apps-list.png)

## 它解决什么问题

厂商的卸载程序很少把东西删干净，通常留下三类东西：

- **目录**：`Program Files`、`ProgramData`、`AppData` 里的应用文件夹
- **注册表**：`HKCU/HKLM\SOFTWARE` 下的配置键
- **后台**：卸载后还在的自启项、服务、计划任务

CleanSweep 在你点完卸载之后继续做事：扫描残留 → 让 AI 逐项判断「可删 / 谨慎 / 保留」→ 你确认 → 删除 → 复查是否真的干净。

## 能做什么

| 功能 | 说明 |
| --- | --- |
| 卸载与清残留 | 执行注册表里的官方卸载命令，结束后自动扫描残留 |
| AI 逐项判定 | 标出可删 / 谨慎 / 保留，还能推断规则扫不到的位置 |
| 卸载复查 | 删完由 AI 判断「算不算卸载干净」，剩下什么、为什么留 |
| 强制删除 | 没有卸载程序、卸载器跑不起来时的兜底，删除前先建系统还原点 |
| 权限管理 | 禁止程序联网、调整 Store 应用权限、管理开机自启 |

## 卸载只有三步

**确认 → 卸载与 AI 分析 → 清理与复查**

1. **确认**：显示实际会执行的卸载命令，附 AI 风险摘要。没配 AI 时这一步就拦住，不做「跳过 AI」的降级。
2. **卸载与分析**：卸载、等进程退出、扫残留、AI 判断，四件事串起来跑，不用手点扫描。结果页直接给结论——建议清理几项、占多少空间，几项要谨慎，几项建议保留。
3. **清理与复查**：确认后删除，完事自动复查——剩下的只是你自己的配置就判「已卸载干净」，还有程序文件就标「仍有 N 项残留」。

## 安装

从 GitHub 的 **Releases** 页面下载：

| 文件 | 用途 |
| --- | --- |
| `CleanSweep_<version>_x64-setup.exe` | 双击安装，推荐 |
| `CleanSweep_<version>_x64_en-US.msi` | 企业批量部署 |
| `CleanSweep.exe` | 免安装绿色版 |

- 启动会弹 UAC：删除 `Program Files`、修改 `HKLM` 注册表、调整防火墙都需要管理员权限，点「否」就只能看不能清。
- 安装包暂未签名，SmartScreen 可能拦一下：更多信息 → 仍要运行。

## 第一次使用

1. **配 AI**：设置 → AI 配置，选 OpenAI / DeepSeek / OpenRouter / 通义千问 / Ollama / LM Studio，或填任意 OpenAI 兼容地址。本地模型不用填 Key。**卸载依赖 AI**，没配好时「卸载并分析残留」按钮点不动。
2. **找软件**：软件页搜索（`Ctrl K`）或按来源筛选，点一行原地展开详情。
3. **卸载**：点「卸载并分析残留」，照向导走完三步。

## 安全边界

- 系统目录（`Windows`、`System32`、`WinSxS`、`WindowsApps`）、系统注册表子树、关键服务、Windows 内置计划任务、系统组件 / 驱动 / 运行库——扫描阶段直接排除，AI 说什么也不放行。
- AI 推断的每一条都要过后端校验（真实存在、绝对路径且非链接、落在应用数据根下、名字相关、不属于其他软件），过不了就丢弃；推断出来的项单独标「AI 推断」。
- 删除只认本次扫描的后端索引，前端传的路径不被信任，删前还会再校验一次路径形态。
- 删除走 `remove_dir_all`，**不进回收站**；强制删除会先建系统还原点兜底。
- 不收集账号、不上传文件内容、无遥测；API Key 与卸载历史只存在 `%APPDATA%\CleanSweep\`。

## 常见问题

**AI 是必需的吗？**
卸载必需，其他功能不依赖。不想用云端就配 Ollama / LM Studio。

**AI 会不会编一个不存在的路径让我删？**
不会进清单：五道校验全过才算候选，删除时再校验一次，而且只认后端索引。

**能一次卸多个软件吗？**
不能。并发卸载会互相抢文件锁，「是否卸完」也会判断不准。

**删错了能恢复吗？**
不能。文件删除不进回收站；强制删除前建的系统还原点是唯一的后悔药。

**提示 os error 740？**
当前进程没有管理员权限——重启程序，UAC 弹框点「是」。

**卸载后还有残留？**
到「卸载历史」找到这条记录，点「重新扫描残留并 AI 判断」。

还有执行什么命令、为什么需要管理员、受保护条目、静默参数、联网等问题，见[常见问题详解](docs/details.md#常见问题)。

## 开发

```bash
pnpm install
pnpm tauri dev                                          # 开发模式，启动时申请管理员权限
pnpm build                                              # 构建前端
pnpm tauri build                                        # 打包 msi / nsis
cargo test --manifest-path src-tauri/Cargo.toml --lib   # Rust 测试
```

技术栈：Tauri 2 + Rust，React 18 + TypeScript + Vite，SQLite（本地历史），OpenAI 兼容接口。目录结构与各模块职责见[技术说明](docs/details.md#技术栈与项目结构)。

## 限制

- 未签名、无自动更新、未启用严格 CSP。
- 名字匹配有边界：残留目录与软件名毫无关系时会漏，靠 AI 推断补，极端命名仍需手动定位。
- 文件关联与 `App Paths` 暂未纳入自动清理。
